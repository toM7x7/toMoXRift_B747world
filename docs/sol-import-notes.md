# GPT-5.6 Sol 展示取り込み

- 原本: `D:/personal_dev/blender/B747_GPT-5.6Sol/B747_Airport_Experience.blend`
- 制作モデルの表記根拠: ユーザー指定フォルダ名。README内に別のLLM名記録なし。
- 原本を開いてメモリ内で変換し、保存せず終了。原本SHA256は読戻し検証で一致。

## 成果物

- `public/sol-main.glb`: 機体、機内、構造、分解エンジン、エプロン、ターミナル、ジェットブリッジ、GSE、人物、見学案内、格納庫。30,054,900 bytes、714,776三角形、12メッシュ、44材質プリミティブ。
- `public/sol-background.glb`: 遠景の草地・滑走路・中心線15オブジェクト。22,936 bytes、180三角形。
- `public/sol-collision.glb`: 原形状と同座標のエプロン、客室床、貨物床、コックピット床、搭乗口床、上下階段。256,328 bytes、34メッシュ、3,576三角形。

アニメーションはエンジンの11クリップを保持、各10秒。再生はランタイム側で制御する。カメラとライトは除外し、ワールド共通照明を使用する。元のGLBでは32材質すべてが灰色だったため、Blenderに保存されたdiffuse_colorのRGBAを反映する取り込み補正を実施。記録済みの透明度を持つ4材質はBLENDへ変換した。新しい色は設定しておらず、metallic・roughness等は既存値を維持。草地の材質は遠景へ移動。

描画負荷を抑えるため、修飾子を評価した後、静的形状を1メッシュ、動く形状をアニメーションの親ごと11メッシュに結合。フレーム1/120の三角形数は不変で、最大bounds差は0.000000238m。元データの共有メッシュを結合するため、ファイル容量は増える。

## 原作由来の制約と確認範囲

- 一部の分解エンジン子部品は地面下約2.16mまである。比較対象として原位置を保持した。
- 上部客室床に階段開口がない。階間移動はテレポート併用が必要。
- 移動階段の段差は約0.377m。実ランタイムの踏破性は別途確認する。
- 衝突形状は床と階段のみ。座席、外板、車両、手すり、ターミナル外壁を阻害物にはしていない。
- Blender形状計測と最終GLBの構造読戻しは合格。実ブラウザ・VRでの見え方と歩行確認はワールド統合作業側で行う。

## 保存色の取り込み補正

元生成コードはノード名を英語のPrincipled BSDFで検索していたが、保存ファイルの実ノード名は「プリンシプルBSDF」だった。このためdiffuse_colorには作品の色が保存された一方、実シェーダーと既存GLBはすべてbaseColor=[0.8,0.8,0.8,1]のままだった。主展示・遠景のglTF材質に保存RGBAを反映し、形状・アニメーションのBINチャンクがバイト単位で不変であることを確認した。原本は保存していない。

証拠は docs/sol-material-source.json、補正処理は scripts/sol-restore-material-colors.py。再書き出し処理からも自動的に補正する。比較展示案内には「保存色の取り込み補正あり」と明示する。
